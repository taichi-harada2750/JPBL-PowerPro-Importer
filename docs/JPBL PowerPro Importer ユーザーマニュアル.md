# JPBL PowerPro Importer ユーザーマニュアル

パワプロの試合成績スクリーンショットから、JPBL 成績入力 GAS 用の GameJSON を作成する手順です。

JPBL PowerPro Importer は、野手記録または投手記録の画像を OCR で読み取り、利用者が確認・修正した成績を `GameJSON v1` として保存する Windows 向けローカルツールです。OCR の結果は自動入力の補助であり、書き出す前に必ず確認してください。

## 1. できること

- 野手記録・投手記録のスクリーンショットを OCR で読み取る
- NameList に登録された正式選手名と OCR 結果を照合する
- 成績、選手名、投手判定、備考を画面上で修正する
- 野手・投手の成績を 1 つの GameJSON ファイルとして保存する

出力した JSON ファイルは、JPBL 成績入力 GAS で使用します。本ツールから GAS へ直接送信する機能はありません。

## 2. 推奨環境

| 項目 | 推奨内容 | 理由 |
| --- | --- | --- |
| OS | 64 ビット版 Windows 10 または Windows 11 | Windows 向け実行ファイルとして配布されます。 |
| CPU | Intel Core i5 または AMD Ryzen 5 相当以上 | OCR は CPU で実行されます。 |
| メモリ | 8 GB 以上、16 GB 推奨 | PaddleOCR と画像処理を安定して実行するためです。 |
| 空き容量 | 3 GB 以上 | 配布フォルダー、認識モデル、作業用キャッシュ、出力ファイルのために余裕を確保します。 |
| 画像 | 1920×1080 の成績画面を PNG で保存 | 画面レイアウトは 1920×1080 の野手・投手記録画面を基準に調整されています。 |
| ネットワーク | 初回 OCR モデル準備時はインターネット接続を推奨 | 環境や配布内容によっては、初回解析時に日本語認識モデルを準備します。 |

通常の画像解析と JSON 作成はローカルで行います。上記は快適に利用するための目安であり、低いスペックでも動作する場合があります。

## 3. 用意するもの

- `JPBL PowerPro Importer` の配布フォルダー一式
  - EXE だけを別の場所に移動せず、フォルダーごと展開してください。
- 対象球団の NameList JSON ファイル
  - 選手名の照合候補は NameList を基準にします。
- 野手記録または投手記録のスクリーンショット
  - 対応形式は PNG、JPG、JPEG、BMP、WebP です。

## 4. 起動方法

1. 配布された ZIP ファイルを任意のフォルダーへ展開します。
2. 展開先の `JPBL PowerPro Importer` フォルダーを開きます。
3. `JPBL PowerPro Importer.exe` をダブルクリックします。
4. 初回の OCR モデル準備が完了するまで待ちます。

通常の利用では EXE 配布版を使用してください。開発環境から起動する場合は、Python 3.11 以上と `requirements.txt` の依存関係が必要です。

## 5. 初期設定

### 5.1 NameList を読み込む

1. 画面上部の **NameList** カードで **変更** を選びます。
2. 配布または管理されている NameList JSON ファイルを選択します。
3. 表示が **読込済** になり、球団の候補が表示されることを確認します。

最後に使用した NameList の場所は記憶されます。次回起動時、そのファイルが同じ場所にあれば自動で読み込みます。NameList を更新したときは **変更** から新しいファイルを選んでください。

### 5.2 NameList の形式

NameList は `schemaVersion` が `1` または `2` の JSON です。各球団に `batters` と `pitchers` の配列が必要です。球団名・選手名は空欄にできず、同じ球団・同じ区分内で選手名を重複させることはできません。

`schemaVersion: 2` では、各球団に `aliases` を追加できます。`aliases.batters` と `aliases.pitchers` は、パワプロ表示名から同じ球団・同じ区分の正式名への対応表です。Alias は完全一致だけで使用され、部分一致やあいまい一致は行いません。Alias の変換先は必ず対応する正式名一覧に存在する必要があります。

```json
{
  "schemaVersion": 1,
  "teams": {
    "湘南": {
      "batters": ["京極遥人"],
      "pitchers": ["鈴鹿雄大"]
    }
  }
}
```

### 5.3 ユーザー名と Game ID

**ユーザー設定** の **ユーザー名** には、Game ID の先頭に使う 3 文字の識別子を入力します。入力後にフォーカスを移すか Enter を押すと自動保存されます。空欄のまま使う場合は `UKN` になります。

| 設定項目 | 使い方 |
| --- | --- |
| 球団 | NameList 読み込み後に対象球団を選びます。球団を変更すると、すでに解析した野手・投手の確認テーブルは消去されます。 |
| 成績種別 | **野手記録** または **投手記録** を選びます。切り替えると画像選択だけがリセットされます。野手と投手を同じ球団で順に解析すれば、両方を 1 つの GameJSON にまとめられます。 |
| 試合日 | `YYYY/MM/DD` を推奨します。`YYYYMMDD`、`YYYY-MM-DD`、`M/D`、`M-D` も Game ID 生成に使えます。`M/D` と `M-D` は現在の年として扱われます。 |
| Game ID | 通常は `ユーザー名-球団コード-YYYYMMDD-通し番号` の形式で自動生成されます。例: `ABC-BT-20261005-001`。末尾の通し番号は必要に応じて直接修正できます。 |

> **重要:** 試合日を上記以外の形式にすると、Game ID の日付部分には当日の日付が使われます。書き出す前に Game ID と試合日の両方を確認してください。

## 6. 画像を準備する

### 6.1 良い画像の条件

- パワプロの成績表全体が見え、選手名列と数値列の罫線が欠けていない画像を使います。
- 野手記録には野手記録、投手記録には投手記録を選びます。画面種別と画像を混在させないでください。
- スクロールが必要な場合は最大 2 枚まで選べます。必ず上側の画像、下側の画像の順で選択します。
- 2 枚の画像に重複して写った選手は、NameList 照合結果を使って 1 行に統合されます。
- 画面全体のスクリーンショットを推奨します。黒帯付きのキャプチャは中央の 16:9 のゲーム画面を検出できる場合がありますが、成績表が極端に切れている画像は避けてください。

### 6.2 画像を選択して解析する

1. 球団と成績種別を確認します。
2. **成績画像** カードの **画像を選択** を選び、1 枚または 2 枚の画像を選択します。
3. ファイル名が成績画像カードに表示されたら、**画像を解析** を選びます。
4. 解析後、確認テーブルと行プレビューで結果を確認します。

画像ファイルをウィンドウへドラッグ＆ドロップして追加することもできます。すでに 1 枚選択済みの場合は、2 枚目だけをドロップできます。

画像を選び直すときは **画像をリセット** を使います。この操作は画像選択だけを消去し、確認済みの表データは消去しません。

## 7. 解析結果を確認して修正する

### 7.1 確認テーブルの状態

| 状態 | 意味 | 利用者がすること |
| --- | --- | --- |
| `OK` | 名前と必要な数値が確認済みです。 | 内容を目視確認し、問題がなければそのままにします。 |
| `要確認` | OCR の名前候補が低い一致度または僅差の候補です。 | 選手名を選び直すか、状態セルをダブルクリックして確認済みにします。 |
| `エラー` | 正式名が未選択、または必要な数値が未入力です。 | 選手名と赤く表示された入力欄を修正してから書き出します。 |

行を選択すると、画面下部に成績表見出しと選択行の画像が表示されます。OCR 名、数値、画像を見比べながら確認してください。確認理由や OCR 名にマウスを置くと、候補名と一致度を確認できます。

### 7.2 野手記録を確認する

野手テーブルでは、次の項目を確認します。

- 打数、得点、安打、二塁打、三塁打、本塁打、打点、三振
- 四死球、犠打、盗塁、併殺、失策、犠飛
- 選手名、備考

**試合** は GameJSON の固定値 `1` です。数値欄は `0` 以上の整数で入力します。空欄は未確認としてエラーになります。

現在の野手記録画面には犠飛列がないため、犠飛は `0` として設定されます。必要なら確認テーブルで修正してください。野手記録の赤色の投手行は解析対象から除外されます。

### 7.3 投手記録を確認する

投手テーブルでは、次の項目を確認します。

- 投球回、投球回分数、球数、打者、被安打、奪三振、四死球
- 失点、自責点、暴投、被本塁打
- 先発、勝利、敗戦、H、S、完投、完封、無四球、敬遠数
- QS、HQS、選手名、備考

投球回分数は `0`、`1`、`2` のいずれかを選びます。勝利、敗戦、H、S は画面の判定を OCR で読みますが、必ず実際の試合結果と照合してください。

| 項目 | 初期値または計算方法 | 確認ポイント |
| --- | --- | --- |
| 先発 | 投手一覧の先頭行を先発として設定 | 先発投手が正しいか確認します。 |
| 完投 | 投手が 1 人だけ、または投球回が 9 回以上の場合に設定 | 継投・延長戦では実際の記録に合わせて修正します。 |
| 完封 | 完投かつ失点 0 の場合に設定 | 必要に応じて手動で修正できます。 |
| 無四球 | 完封かつ四死球 0 の場合に設定 | 四死球の確認後に見直します。 |
| QS | 投球回が 6 回以上、かつ自責点 3 以下で `1` | 投球回・投球回分数・自責点の編集後に自動更新されます。 |
| HQS | 投球回が 7 回以上、かつ自責点 2 以下で `1` | 投球回・投球回分数・自責点の編集後に自動更新されます。 |

先発、完投、完封、無四球は初期値の後でも変更できます。手動で変更した値は、その後に OCR 数値を修正しても自動計算で上書きされません。

### 7.4 備考を入力する

各選手行の **備考** は任意です。書き出すと各選手の `adds.備考` にそのまま保存されます。入力しない場合は空文字列で出力されます。

## 8. GameJSON を書き出す

1. 野手・投手ともに必要な行を確認し、状態が `OK` になっていることを確認します。
2. 画面上部の **Game ID** と **試合日** を確認します。
3. **GameJSONを書き出す** を選び、保存先を指定します。
4. 保存完了の通知を確認します。既定のファイル名は `JPBL_Game_<Game ID>.json` です。

書き出しに成功すると、Game ID の通し番号が次の番号へ進みます。保存を取り消した場合や書き出しに失敗した場合は進みません。

### 8.1 出力内容

出力ファイルは UTF-8 の JSON です。最上位には `gameId` と `players` があり、各選手には `name`、`team`、`position`、`adds` が入ります。OCR の生データや一致度は出力されません。

```json
{
  "gameId": "ABC-BT-20261005-001",
  "players": [
    {"name": "京極遥人", "team": "湘南", "position": "野手", "adds": {}},
    {"name": "鈴鹿雄大", "team": "湘南", "position": "投手", "adds": {}}
  ]
}
```

同じ球団について野手と投手を順に解析した場合、両方の確認テーブルの選手が 1 つの `players` 配列に書き出されます。球団を変更すると既存の表データは消去されるため、別球団の成績は別の GameJSON として出力してください。

## 9. よくある問題と対処

| 症状 | 確認すること | 対処 |
| --- | --- | --- |
| **画像を解析** ボタンが押せない | NameList、球団、成績画像がそろっているか | NameList を読み込み、球団を選び、1〜2 枚の対応画像を選択します。 |
| 選手行を検出できない | 成績表の罫線と選手名列が画像に含まれているか。野手・投手の種別が正しいか | 画面全体のスクリーンショットを選び直します。解決しない場合は画像と成績種別を管理者へ共有してください。 |
| 名前が違う、要確認になる | NameList が最新か。選択球団が正しいか | 選手名のプルダウンから正式名を選び、必要なら状態セルをダブルクリックして確認済みにします。 |
| 数値欄が赤い、または空欄 | OCR が文字を数字として確定できたか | 元画像と見比べ、`0` 以上の整数を入力します。空欄のままでは書き出せません。 |
| PaddleOCR を初期化できない | 初回モデル準備時のネットワーク、空き容量、ウイルス対策ソフトのブロック | アプリを閉じて接続と空き容量を確認し、再起動します。続く場合は `%LOCALAPPDATA%\JPBL PowerPro Importer\logs\paddleocr-initialization.log` を添えて管理者へ連絡します。 |
| GameJSON を書き出せない | 画面にエラーが残っていないか。Game ID と試合日が空欄でないか | エラーに示された選手名または数値を修正します。試合日は `YYYY/MM/DD` を使うと確実です。 |

## 10. 運用チェックリスト

### 解析前

- [ ] 最新の NameList を読み込んだ。
- [ ] 対象球団と成績種別を選んだ。
- [ ] 成績表全体が写った画像を選んだ。2 枚の場合は上側から下側の順にした。
- [ ] ユーザー名、試合日、Game ID を確認した。

### 書き出し前

- [ ] すべての行で選手名と数値を元画像と照合した。
- [ ] 要確認の行は選手名を選び直すか、状態を確認済みにした。
- [ ] 投手の勝敗、H、S、先発、完投、完封、無四球を確認した。
- [ ] 備考が必要な選手に入力した。
- [ ] Game ID と試合日が正しい。
- [ ] 保存先と保存後の JSON ファイルを確認した。

## 11. 注意事項

本ツールは成績表の OCR と GameJSON 作成を補助するものです。文字のつぶれ、画像圧縮、画面レイアウトの変更、スクロール位置などにより誤認識することがあります。保存前に確認テーブルと行プレビューで必ず目視確認してください。

出力した GameJSON、使用した NameList、元のスクリーンショットは、成績入力が完了するまで同じ試合単位で保管することを推奨します。差し戻しや修正が必要になった場合に、入力内容を確認できます。
